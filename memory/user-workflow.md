Для фич пользователь требует поэтапный процесс с явными подтверждениями:
`/create-spec` → пользователь читает спеку и сам вписывает ответы на Open
Questions прямо в файл → подтверждает → план в `plans/` → пользователь
читает/правит → подтверждает → только тогда реализация. Не перепрыгивать
этапы; перед планом и перед кодом ждать явного «подтверждаю».

Git делает сам: создаёт ветку (напр. `forms`), сам `git add`/`commit`/`push`
своими формулировками. Я код не коммичу, если не попросят — только сообщаю,
что осталось закоммитить, и предлагаю команды.

**Why:** пользователь хочет контролировать каждый шаг и владеть историей git.
**How to apply:** уточняющие вопросы задавать на этапе спеки/плана; после
правок резюмировать решения; коммит-сообщения и ветки — за пользователем.
См. [[forms-build-playbook]].
