Спецификация: `specs/modal-lead-form.md` (согласована).
Затрагиваемые файлы: `index.html`, `css/style.css`, `js/main.js`,
новый `privacy.html`. Без сборки/зависимостей — чистые HTML/CSS/JS.

## Шаг 1. Разметка модального окна — `index.html`

Добавить перед блоком `<!-- Lightweight interaction script -->` (после
чат-виджета, ~строка 588) новый блок модального окна:

- Обёртка-оверлей `.lead-modal` с `hidden`, `role="dialog"`,
  `aria-modal="true"`, `aria-labelledby="leadModalTitle"`,
  `aria-hidden="true"`.
- Внутри `.lead-modal__dialog`:
  - кнопка закрытия `.lead-modal__close` (иконка `solar:close-circle-linear`,
    `aria-label="Закрыть"`);
  - заголовок `#leadModalTitle` («Оставить заявку») + краткий подзаголовок;
  - `<form class="lead-form" novalidate>` с тремя полями:
    - `Ваше имя` — `<input type="text" id="leadName" required>`;
    - `Адрес эл. почты` — `<input type="email" id="leadEmail" required>`;
    - `Номер телефона` — `<input type="tel" id="leadPhone" required
      inputmode="tel" placeholder="+7 (___) ___-__-__">`;
    - у каждого поля `<label for=...>` и пустой `<span class="lead-form__error"
      role="alert">` под полем;
  - блок согласия: `<input type="checkbox" id="leadConsent" required>` +
    label с текстом и ссылкой
    `<a href="./privacy.html" target="_blank" rel="noopener">политики
    обработки персональных данных</a>`;
  - кнопка отправки `<button type="submit" class="btn btn-primary"
    id="leadSubmit" disabled>Отправить</button>`;
  - контейнер статуса `.lead-form__status` (`role="status"`,
    `aria-live="polite"`) для сообщений успех/ошибка.

Триггеры (атрибут-хук, без инлайн-обработчиков): добавить класс
`js-lead-open` к двум существующим кнопкам:
- шапка — `index.html:66` (`.btn.btn-primary`);
- hero — `index.html:107` (`.btn.btn-outline`).

## Шаг 2. Стили — `css/style.css`

Добавить **новую секцию `/* --- Lead Form Modal --- */`** в конец файла
(после секции `/* --- Chat Widget --- */`, ~после строки 1902), чтобы не
ломать существующий порядок секций. Все цвета/шрифты — через переменные
`:root` (`--text-dark`, `--text-muted`, `--primary-btn-bg`, `--font-ui`,
`--font-sans`, `--spacing-*`). Без инлайн-стилей.

Состав:
- `.lead-modal` — фикс-оверлей на весь экран, затемнение
  (`rgba(0,0,0,.5)`), `display:flex` центрирование, `z-index` выше
  чат-виджета, переход opacity; `.lead-modal.hidden { display:none }`.
- `.lead-modal__dialog` — карточка: белый фон, скругление и тень в духе
  чат-окна, max-width ~480px, внутренние отступы, скролл при нехватке
  высоты, анимация появления (fade + лёгкий scale/translateY), уважение
  `prefers-reduced-motion` (расширить существующий блок на ~1636).
- `.lead-modal__close` — кнопка-иконка в углу (паттерн `closeChatBtn`).
- `.lead-form` поля — единый стиль input/label под типографику сайта;
  фокус-стиль; класс `.is-invalid` (красная рамка через `--guide-red`).
- `.lead-form__error` — мелкий текст ошибки цветом `--guide-red`, скрыт
  пока пуст.
- Блок согласия — выравнивание чекбокса и текста, ссылка в стиле сайта.
- Состояния кнопки: `:disabled` (приглушённая), `.is-loading` (текст
  «Отправляем…» / спиннер).
- `.lead-form__status` — варианты `--success` / `--error`.
- Адаптив: внутри существующего `@media (max-width: 768px)` (или новым
  медиа-блоком в этой же секции) — окно почти на всю ширину с отступами,
  крупные тап-зоны.

## Шаг 3. Логика — `js/main.js`

3a. **Константы** рядом с `WEBHOOK_URL` (строки 2–3), помечены как
configuration-sensitive:
```
const TELEGRAM_BOT_TOKEN = '8950625452:AAEK-uFPioBDOyhJHiZTujz2Fz5X-peHxmU';
const TELEGRAM_CHAT_ID = '5268263277';
```

3b. **Новый инициализатор `initLeadFormModal`** (по образцу
`initChatWidget`): объявить рядом с другими `initX`, в конце
`initPageInteractions` добавить вызов `initLeadFormModal();` в список
(после `initChatWidget();`). No-op, если элементы модалки отсутствуют.

Внутри:
- Сбор ссылок на элементы; ранний `return`, если модалки нет.
- `openModal(triggerEl)`: снять `hidden`, `aria-hidden=false`, запомнить
  триггер для возврата фокуса, заблокировать скролл body
  (класс `body.modal-open { overflow:hidden }` — добавить в CSS),
  перевести фокус на первое поле.
- `closeModal()`: вернуть `hidden`/`aria-hidden`, вернуть фокус на триггер,
  снять блокировку скролла. **Запрет закрытия во время отправки**
  (`isSending`) — кроме явного запрета? → закрытие разрешаем, но запрос
  не отменяем; повторно фиксируем в спеке поведение: при закрытии во
  время отправки запрос продолжается, по ответу — без UI (окно закрыто).
  *(уточнить на ревью плана — см. «Вопрос 1».)*
- Навешивание: клик по `.js-lead-open` → `openModal`; клик по
  `.lead-modal__close` → close; клик по оверлею (target === оверлей) →
  close; `keydown` Escape → close (по образцу чат-виджета).
- **Focus trap**: обработчик `keydown` Tab внутри диалога, цикл по
  фокусируемым элементам (паттерн стандартный, реализуется вручную).
- **Маска телефона** на `input` поля `leadPhone`: нормализация цифр,
  ведущая `8`→`7`, форматирование в `+7 (XXX) XXX-XX-XX`, ограничение
  длины.
- **Валидация** (`validate()`):
  - имя — `trim()` непустое;
  - email — regex формата;
  - телефон — ровно 11 цифр, начинается с 7;
  - чекбокс — отмечен (также гейтит `disabled` кнопки на `change`).
  - При ошибке: класс `.is-invalid` + текст в `.lead-form__error`
    соответствующего поля; фокус на первое невалидное.
- **Submit** (`submit` формы, `e.preventDefault()`):
  - гейт `isSending` (как в чат-виджете) + `submit.disabled`,
    `.is-loading`;
  - сформировать текст сообщения (экранирование значений через
    переиспользуемый `escapeHtml` перед вставкой в HTML-режиме Telegram,
    либо отправлять `parse_mode` не задавать и слать plain text —
    выбираем **plain text без parse_mode**, чтобы исключить инъекцию и
    проблемы экранирования);
  - `fetch('https://api.telegram.org/bot<TOKEN>/sendMessage', { method:
    'POST', headers JSON, body: { chat_id, text } })` с
    `AbortController` и `REQUEST_TIMEOUT_MS` (вынести/переиспользовать
    хелпер `postWithTimeout`-подобный — он сейчас локален в чат-виджете;
    в плане: вынести таймаут-fetch в общий хелпер уровня
    `initPageInteractions` и переиспользовать в обоих местах);
  - успех (`resp.ok` && `result.ok`): показать success-статус, очистить
    поля и чекбокс, вернуть кнопку в исходное; окно оставить открытым с
    сообщением благодарности;
  - ошибка/таймаут: error-статус, поля **не** очищать, кнопку разблокировать.
  - `finally`: снять `isSending`/`.is-loading` (кнопка остаётся `disabled`
    пока чекбокс не отмечен — учесть как в спеке про чат: логика гейта
    через состояние, не безусловное включение).

Текст сообщения в Telegram (plain):
```
Новая заявка с сайта Amigo
Имя: <name>
E-mail: <email>
Телефон: <phone>
Источник: <шапка|hero>, <URL страницы>
Время: <ISO>
```

## Шаг 6. Ручная проверка (нет автотестов)

Открыть `index.html` (Start-Process), проверить по чек-листу спеки:
1. Обе кнопки «Оставить заявку» открывают одно окно.
2. Закрытие: крестик / клик по фону / Esc; скролл фона заблокирован.
3. Focus trap и возврат фокуса на триггер.
4. Валидация: пустые поля, плохой email, короткий телефон, чекбокс.
5. Маска телефона форматирует ввод.
6. Кнопка submit заблокирована без чекбокса.
7. Реальная отправка → сообщение приходит в Telegram-бота
   `amigo_igc_bot` (chat_id 5268263277); проверить успех-UI.
8. Имитация ошибки (неверный токен / оффлайн) → error-UI, поля целы.
9. Ссылка на `privacy.html` открывается в новой вкладке, страница в
   стиле сайта.
10. Десктоп + мобильная ширина (DevTools).
