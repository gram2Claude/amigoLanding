# План реализации: страница «Как работает Amigo» (product.html)

Источник истины — `specs/product-page.md` (утверждён). Этот файл —
пошаговый план исполнения. Коммиты/мерж выполняет заказчик.

## Предусловия / разведка (перед правками)
- Образец каркаса: `privacy.html` (head, шапка, футер, подключение CSS).
- Откуда копировать `#leadModal`: разметка модала в `index.html`
  (+ его data-атрибуты демо-режима с существующей демо-кнопки).
- Текущая версия кеш-бастинга в репозитории: `v=48` → целевая `v=49`.
- Логотипы источников в `assets/images/logos/` (проверено):
  - есть: `01_yandex_direct.png` (Яндекс Директ), `02_yandex_metrika.png`
    (Яндекс Метрика), `04_vk_ads.png` (VK Ads), `05_my_target.png`
    (MyTarget), `06_rtb_droid.png` (RTB Droid);
  - **нет: e-commerce, Hybrid, ПланФакт** → шаг 4.

## Шаг 1. Ассеты-изображения
1.1. `source-materials/new-page/scheme_transparent_bg.png` → оптимизировать
     (прозрачный PNG, без потери читаемости) → `assets/images/product-data-flow.png`.
1.2. `source-materials/new-page/04_01_refresh_data.png` → оптимизировать →
     `assets/images/product-data-refresh.png`.
1.3. Недостающие логотипы (e-commerce, Hybrid, ПланФакт): найти в
     `source-materials/new-page/_pptx_extract/ppt/media/`, вырезать/очистить
     фон, оптимизировать → `assets/images/logos/` по конвенции имён
     (`*_raw` оригинал при необходимости). Если качество негодное —
     fallback: текст-чип в стиле сайта (решение зафиксировать в коде
     комментарием). Размер изображений — разумный, без мегабайтных файлов.
- Проверка: размеры файлов уменьшены, картинки открываются, фон прозрачный
  где нужно.

## Шаг 2. `product.html` — каркас
2.1. Скопировать структуру `privacy.html`: `<head>` (шрифты, Iconify,
     favicon, `<title>`/meta под «Как работает Amigo»), шапка с логотипом и
     навигацией, `<footer>`.
2.2. Подключить `./css/style.css?v=49`; перед `</body>` —
     `./js/main.js?v=49`.
2.3. Навигация шапки/футера: пункты-якоря ведут на `index.html#anchor`
     (а не на локальные `#`), чтобы возврат на главную работал.
2.4. Язык ru, семантика, доступность: иерархия заголовков, `alt`,
     `aria-label`.

## Шаг 3. Контент-секции (FR-2, расширенный объём)
Секции по порядку, классы — из общего CSS (секции/контейнеры/заголовки
сайта), без параллельных стилей где есть готовые:
- `0` Hero (без `id`): H1 «Как работает Amigo», подзаголовок, лид 2–3 фразы.
- `#problem` Проблема — 5 тезисов слайда 2 с пояснениями.
- `#what` Что такое Amigo — конвейер процессов + цели/микросервисы (Google-док).
- `#data-flow` Поток данных — текст конвейера + `product-data-flow.png`.
- `#sources` Источники — логотипы (5 из репо + 3 добор/чип), список.
- `#reports` Уровни отчётов — перечень уровней (слайд 7).
- `#freshness` Актуальность данных — механика + `product-data-refresh.png`.
- `#monitoring` Мониторинг — слайд 11 (без ролей).
- `#demo` Финальный CTA — `<button class="p-btn js-lead-open"
  data-lead-title="Получить демо доступ" …>` с теми же data-атрибутами,
  что демо-кнопка `index.html`.
- Контент синтезировать: факты — приоритет Google-док, тон/структура —
  презентация; противоречий не «додумывать».

## Шаг 4. Внутристраничный навигатор (FR-1b/2a)
4.1. Разметка: в `<body>`, сразу под `<header>`, отдельная статичная полоса
     (НЕ sticky) — список из **6** текстовых ссылок-якорей:
     Проблема `#problem`, Что такое Amigo `#what`, Поток данных
     `#data-flow`, Источники `#sources`, Уровни отчётов `#reports`,
     Актуальность данных `#freshness`. («Мониторинг»/CTA — НЕ в навигаторе.)
4.2. CSS: новая секция в `css/style.css` (стилистика сайта, `:root`-перем.),
     ссылки переносятся на узких экранах (flex-wrap), активный — подчёркнут.
     Не оборачивать в `prefers-reduced-motion … none` (Variant B). Учесть
     scroll-offset, чтобы заголовок секции не уезжал под край.
4.3. JS: добавить самодостаточный `initX` в `js/main.js` (паттерн файла —
     no-op при отсутствии элементов) для **scroll-spy**: подсветка активного
     пункта при скролле + плавный скролл по клику. Зарегистрировать в
     `initPageInteractions()`. Никакой инъекции пользовательского текста
     (escapeHtml не требуется здесь).

## Шаг 9. Проверка (Playwright, dev-only)
9.1. `reducedMotion: 'reduce'` (целевая среда). Прогнать desktop и ≤768px.
9.2. Чек-лист:
     - навигатор виден под шапкой, 6 пунктов, переносится на мобиле;
     - scroll-spy переключает активный пункт; клик → плавный скролл к секции,
       заголовок не под краем;
     - все 6 якорей + `#monitoring`/`#demo` существуют (нет «битых»);
     - демо-кнопка открывает `#leadModal` в режиме демо;
     - бургер ≤768px работает; cookie-баннер появляется;
     - ссылки «О нас» (index шапка/футер) ведут на product.html;
     - страница визуально неотличима по стилю от сайта (FR-1a);
     - консоль без ошибок;
     - изображения не тяжёлые.
9.3. Скриншоты в `tools/screenshots/` (gitignored).
