## Summary

Добавить модальное окно с формой заявки, которое открывается по клику на кнопку
**«Оставить заявку»**. Форма собирает имя, e-mail и телефон пользователя,
требует согласия на обработку персональных данных и отправляет заявку
**в Telegram-бота `t.me/amigo_igc_bot`** через Telegram Bot API.

Стилистика модального окна и формы должна полностью соответствовать текущему
дизайну сайта (цвета и переменные из `:root` в `css/style.css`, скругления,
тени, типографика, стиль кнопок `.btn`/`.btn-primary`).

Дополнительно создаётся отдельная страница политики обработки персональных
данных, на которую ссылается текст-предупреждение в форме.

## Решения (ответы заказчика)

1. **Доставка заявки — напрямую в Telegram Bot API.** Браузер вызывает
   `https://api.telegram.org/bot<TOKEN>/sendMessage` с `chat_id` и текстом
   заявки. Бэкенд не используется.
   - ⚠️ **Нюанс безопасности (зафиксирован, принят заказчиком):** токен бота
     и `chat_id` будут видны в публичном `js/main.js`. Любой посторонний
     сможет отправлять сообщения в этого бота напрямую и потенциально
     спамить чат заявок. Это осознанный компромисс ради отсутствия бэкенда.
   - Для реализации заказчик предоставляет: **токен бота** и **`chat_id`**
     (id чата/группы, куда бот шлёт заявки). См. «Open Questions».
2. **Кнопка в hero-блоке** (`index.html:107`) — да, открывает то же
   модальное окно.
3. **Чекбокс согласия** — да, отдельный обязательный чекбокс; submit
   недоступен без галочки.
4. **Политика ПДн** — разработать отдельную страницу с текстом; форма на неё
   ссылается.
5. **Телефон** — строгая валидация по российскому формату, с маской ввода.
6. **Доп. поля** — не нужны, строго три поля.
7. **Аналитика** — не нужна.

## Functional Requirements

### Триггер открытия

- Кнопка `.btn-primary` «Оставить заявку» в шапке (`index.html:66`) открывает
  модальное окно.
- Кнопка `.btn-outline` «Оставить заявку» в hero-блоке (`index.html:107`)
  открывает то же модальное окно.

### Модальное окно

- Затемнённый оверлей на весь экран поверх контента; форма по центру.
- Закрытие: крестик в углу формы, клик по оверлею вне формы, клавиша `Esc`.
- Блокировка прокрутки фона при открытом окне.
- Доступность: `role="dialog"`, `aria-modal="true"`, `aria-labelledby`
  на заголовке; фокус переводится в окно при открытии и возвращается на
  кнопку-триггер при закрытии; focus trap внутри окна.
- Анимация появления/закрытия в духе сайта (плавный fade/scale).

### Поля формы

| Поле | Тип | Обязательное | Валидация |
|------|-----|--------------|-----------|
| Ваше имя | text | да | непустое, обрезка пробелов |
| Адрес эл. почты | email | да | формат e-mail |
| Номер телефона | tel | да | российский формат, маска `+7 (___) ___-__-__` |

- У каждого поля видимый `<label>` и связь через `for`/`id`.
- Телефон: маска ввода `+7 (XXX) XXX-XX-XX`, строгая клиентская валидация
  (11 цифр, начинается с 7/8 → нормализуется к `+7XXXXXXXXXX`).
- Сообщения об ошибках под полем (на русском), стилизованы под сайт.

### Согласие на обработку персональных данных

- Отдельный **обязательный чекбокс** «Я согласен на обработку персональных
  данных» под полями; пока он не отмечен — кнопка отправки недоступна.
- Рядом с чекбоксом — текст со ссылкой на страницу политики обработки ПДн
  (открывается в новой вкладке).

### Страница политики обработки персональных данных

- Новая статическая страница (например, `privacy.html`) в корне репозитория,
  оформленная в стиле сайта (та же шапка/типографика/цвета, переиспользование
  `css/style.css`).
- Содержит типовой текст политики обработки ПДн на русском: оператор,
  цели обработки, перечень данных (имя, e-mail, телефон), правовые основания,
  согласие, срок хранения, права субъекта, контакты.
- ⚠️ Текст — типовой шаблон, не является юридической консультацией; заказчику
  рекомендуется проверить у юриста (см. Open Questions).

### Отправка

- Submit формирует текст заявки и вызывает Telegram Bot API
  (`sendMessage`) с `chat_id` и телом заявки (имя, e-mail, телефон,
  отметка источника/времени).
- Защита от повторной отправки: блокировка кнопки и индикатор загрузки на
  время запроса (паттерн флага `isSending` из чат-виджета).
- Тайм-аут запроса через `AbortController` (переиспользовать подход
  `REQUEST_TIMEOUT_MS` из `js/main.js`).
- Успех: сообщение об успешной отправке внутри окна, очистка полей и чекбокса.
- Ошибка: понятное сообщение об ошибке, данные в полях сохраняются для повтора.

### Архитектурные соглашения

- JS: новый самодостаточный инициализатор `initLeadFormModal`,
  зарегистрированный в `initPageInteractions()` в `js/main.js`, с проверкой
  существования элементов (паттерн как у `initMobileMenu`/`initChatWidget`).
- Константы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — наверху `main.js`
  рядом с `WEBHOOK_URL`; помечены как configuration-sensitive, изменение
  фиксируется в PR (по аналогии с правилами для `WEBHOOK_URL`).
- HTML: разметка модального окна добавляется в `index.html`;
  страница политики — отдельный файл.
- CSS: правила добавляются в существующую секцию стилей (отдельная секция
  перед media-queries), переменные из `:root`; инлайн-стили не использовать.
- Пользовательский ввод, выводимый в DOM, экранируется через `escapeHtml`.

## Possible Edge Cases

- Отправка пустой/частично заполненной формы → блокируется валидацией.
- Некорректный e-mail или телефон → ошибка под полем, submit не уходит.
- Чекбокс согласия не отмечен → кнопка отправки недоступна.
- Сетевая ошибка / тайм-аут / ошибка Telegram API → сообщение об ошибке,
  поля не очищаются.
- Двойной клик по кнопке отправки → второй запрос не уходит.
- Закрытие по Esc/оверлею в момент отправки.
- Повторное открытие после успешной отправки → форма в исходном состоянии.
- Мобильная ширина: окно помещается на экран, клавиатура не перекрывает поля.
- Вставка HTML/скрипта в поля → не приводит к инъекции (экранирование).
- Telegram API недоступен / неверный токен / неверный chat_id → ошибка
  показывается пользователю как «не удалось отправить, попробуйте позже».

## Acceptance Criteria

- [ ] Клик по «Оставить заявку» в шапке и в hero-блоке открывает одно и то же
      модальное окно с формой.
- [ ] Форма содержит поля: Ваше имя, Адрес эл. почты, Номер телефона — все
      обязательные, с рабочей валидацией и ошибками на русском.
- [ ] Телефон вводится с маской и проходит строгую валидацию рос. формата.
- [ ] Обязательный чекбокс согласия блокирует submit, пока не отмечен;
      рядом — ссылка на страницу политики ПДн.
- [ ] Существует страница политики обработки ПДн в стиле сайта с текстом.
- [ ] Успешная отправка доставляет заявку в Telegram-бота `amigo_igc_bot`
      и показывает подтверждение пользователю.
- [ ] Ошибка отправки показывается пользователю, введённые данные не теряются.
- [ ] Окно закрывается крестиком, кликом по оверлею и Esc; фон не
      прокручивается при открытом окне.
- [ ] Внешний вид окна и формы соответствует стилю сайта.
- [ ] Корректная работа на десктопе и мобильной ширине.
- [ ] Доступность: dialog-семантика, фокус-менеджмент, focus trap, ARIA.
