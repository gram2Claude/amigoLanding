# Spec for Блок «Поток данных и архитектура» — SVG-схема вместо растра

figma_component (if used): —

## Summary

В `product.html`, секция `#data-flow` («Поток данных и архитектура»),
сейчас стоит растровое изображение `assets/images/product-data-flow.png`
(`<figure class="product-figure"><img …></figure>`, стр. 129–133).

Задача: убрать растр и собрать **нативную HTML/CSS/SVG-визуализацию**
конвейера данных из уже готовых векторных логотипов
(`assets/images/vector/*.svg`) + векторных стрелок направления. Схема должна
быть компактнее и пропорциональнее исходного квадратного растра, органично
вписываться в ширину контента страницы и сохранять стиль сайта (FR-1a из
[[product-page]]), адаптив и reduced-motion Variant B.

Это правка контента/вёрстки одной секции; модель, текст списка и остальные
секции страницы не затрагиваются.

## Functional Requirements

### FR-1. Удалить растровое изображение
- Удалить `<figure class="product-figure">` с `img
  src="./assets/images/product-data-flow.png?v=…"` из секции `#data-flow`
  (стр. 129–133).
- Сам файл `assets/images/product-data-flow.png` и его исходники в
  `source-materials/` пока **не удалять** (на случай отката); вопрос об
  удалении файла — см. Open Questions.
- Заголовок `<h2>`, вводный абзац и список `.product-list` из 4 пунктов —
  **оставить без изменений** (см. Open Questions п. 6 — нужно ли уносить
  подписи стадий в диаграмму вместо списка).

### FR-2. Структура визуализации (конвейер)
Воспроизводит логику исходной схемы, слева направо:

1. **Источники** (группа логотипов): `01_yandex_direct.svg`,
   `02_yandex_metrika.svg`, `04_vk_ads.svg`, `05_my_target.svg`,
   `06_rtb_droid.svg`, `09_plan_fakt.svg`, `08_metrika_ecom.svg`
   (e-commerce). Точный набор и порядок — Open Questions п. 1.
2. → **Data Lake** — `clickhouse.svg` + подпись «Data Lake (ClickHouse)».
3. → **Обработка** — узел «Обогащение и парсинг» (текстовый бейдж в стиле
   сайта; готового логотипа нет). Иконка — опционально (Open Questions п. 4).
4. → **Data Mart** — `mySql.svg` + подпись «Data Mart (MySQL)».
5. → **Визуализация** — `powerBi.svg` + `excel.svg` (дашборды/выгрузки).
   Какой Power BI: `powerBi.svg` (плитка) или `power-bi-icon-7.svg` —
   Open Questions п. 2.

- Стадии 2–5 — одиночные узлы; «Источники» — компактная сетка/стек
  логотипов, общим блоком, от которого идёт одна стрелка к Data Lake.
- Каждый логотип — `<img src="./assets/images/vector/<name>.svg?v=N"
  alt="…" loading="lazy" decoding="async">` с осмысленным `alt`; узлы с
  подписью имеют видимый текст-подпись (шрифт/цвет из общего CSS).

### FR-3. Стрелки направления (SVG)
- Между стадиями — векторные стрелки, показывающие направление потока.
- Одна переиспользуемая разметка стрелки (инлайн-SVG или CSS-фон),
  цвет — из палитры сайта (`--text-muted`/`--guide-gray`), не пёстрый.
- **Десктоп:** стрелки горизонтальные (вправо), между колонками-стадиями.
- **Моб. (≤768px):** раскладка перестраивается в вертикальный стек,
  стрелки разворачиваются вниз (↓) — без дублирования разметки, поворотом
  через CSS.
- Стрелки декоративные → `aria-hidden="true"`; смысл передаёт `alt`
  логотипов и подписи + текстовый список (FR-1).

### FR-4. Размер и пропорции
- Не квадрат 1000×973, как растр. Горизонтально-ориентированный блок,
  вписанный в ширину контента (`.product-page`, ~56rem), высота
  скромная (ориентир — desktop ~280–420px, точная подгонка при вёрстке).
- Логотипы нормализованы по высоте (единый визуальный кегль, напр.
  высота лого-узла ~28–40px, источники мельче), чтобы разнокалиберные
  SVG смотрелись ровно.
- На узких экранах — вертикальный стек на всю ширину, без горизонтального
  скролла; картинка не «съезжает».
- Цель — органичнее и легче, чем прежний растр; финальные числа
  согласуются на этапе вёрстки/скриншотов.

### FR-5. Стиль и конвенции проекта
- FR-1a из [[product-page]]: те же шрифты/цвета/отступы/скругления, классы
  и `:root`-переменные из `css/style.css`; новые стили — в секцию
  product-страницы, без инлайн-стилей где есть классы.
- **Reduced-motion Variant B:** не оборачивать декоративную анимацию
  (если будет hover на узлах) в `prefers-reduced-motion … none`; пульс
  `.status-dot` не затрагивается.
- Доступность: у каждого логотипа `alt`; стрелки `aria-hidden`; порядок
  DOM = логический порядок конвейера (слева направо сверху вниз), читается
  скринридером осмысленно.
- **Кеш-бастинг:** правка HTML/CSS → поднять `?v=` во всех местах
  (`index.html`, `privacy.html`, `product.html`) с текущего `v=49` до
  `v=50`; ссылки на SVG-логотипы и стрелки тоже с `?v=50`.

### FR-6. Без новых зависимостей
- Только статический HTML + общий CSS (+ при необходимости инлайн-SVG).
- Никакого JS не требуется (диаграмма статична). Если для адаптива
  достаточно CSS — JS не добавляем.

## Possible Edge Cases
- **Разнокалиберные SVG:** у логотипов разные `viewBox`/пропорции —
  без нормализации высоты ряд будет «прыгать». Нужна единая система
  размеров (по высоте контейнера, `object-fit: contain`).
- **Узкие экраны:** горизонтальный конвейер не влезает → обязателен
  перенос в вертикальный стек с поворотом стрелок; иначе скролл/обрезка.
- **Очень широкий экран:** блок не должен растягиваться неестественно
  (ограничить max-width, центрировать).
- **Прозрачные фоны логотипов:** часть SVG прозрачные, часть с фоном
  (excel — зелёная плитка, powerBi — жёлтая) — на белом фоне секции
  цветные плитки могут выбиваться; согласовать единый вид (Open Q. 2).
- **Кеш:** без поднятия `?v=` вернувшиеся посетители увидят старый растр
  или сломанную вёрстку.
- **Скринридер:** если убрать текстовый список (Open Q. 6), смысл потока
  должен полностью передаваться `alt`/подписями.
- **Сужение исходного списка:** если стадии дублируются и в списке, и в
  диаграмме — избыточность; решить (Open Q. 6).
